GOAL FOR THIS SESSION
Replace the placeholder quality() function in scripts/plot_frontier.py with a real
outcome signal, and build a learned router that beats scripts/baseline_router.py on
the cost–quality frontier. This is an off-policy evaluation problem: there is no
output, no usage, and no quality label in the export — only the model that actually
served each trajectory. We must construct the outcome signal ourselves and estimate
the counterfactual (what a different route would have cost/kept) without ever
running that route for real.

STEP 1 — Structural outcome signal (routing insight criterion)
Extract features from function_call_output text and trajectory shape that plausibly
indicate struggle/failure, without any external model calls:
- error strings / retry patterns in function_call_output
- number of calls vs. expected for similar tasks (outliers)
- backtracking: same function_call name+similar args repeated close together
- trajectory abandoned early vs. reaching a clear "done" assistant message
Build this as scripts/outcome_signal.py with a documented, rerunnable function
estimate_outcome(calls) -> float in [0,1]. Name explicitly, in a comment block,
what this proxy does NOT capture and how it could be wrong — that honesty is scored.

STEP 2 — Off-policy comparison across trajectories (the twist)
Trajectories are naturally randomized-ish by which model served them. Group similar
trajectories (by task features: first-user-text embedding or simpler features like
tool set used, call count, input length) that ran on different models, and compare
their outcome_signal scores. Implement a simple matching or inverse-propensity
weighting estimator in scripts/offpolicy_eval.py — keep it simple and explainable
over clever; document the method so someone else could rerun it. Explicitly log
where the estimate is likely biased (e.g. if harder tasks are systematically routed
to stronger models, comparing raw outcomes across models will look better for the
strong model even if it's not actually needed).

STEP 3 — Learned router
Using the outcome signal + trajectory features, train a simple, interpretable model
(logistic regression or small decision tree over explicit features — no black box)
that predicts the cheapest model likely to keep the outcome, for the FIRST call of a
trajectory only (since one model serves the whole trajectory per the dataset
premise). Put this in scripts/learned_router.py, following the same interface as
baseline_router.py (reads export/, writes results/routes.jsonl) so it's a drop-in
comparison.

STEP 4 — Frontier
Update plot_frontier.py's quality() to use the real outcome_signal instead of the
placeholder. Run baseline_router.py and learned_router.py side by side, plot both
frontiers on the same chart (baseline vs. learned vs. always-cheapest vs.
always-most-expensive vs. random, if time allows) so the improvement is visually
obvious — this is the headline chart for the pitch.

STEP 5 — Sanity + honesty pass
Run everything end to end on the synthetic sample first (make_synthetic_sample.py)
to confirm the pipeline works before touching the real export. Then run on
export/trajectories_v1_00.jsonl. Print a short summary at the end covering:
cost delta vs. baseline, what the outcome signal measures and its known failure
modes, and what the off-policy estimator assumes and where it can break. This
summary is what we'll turn into the presentation's "known weakness" slide.
